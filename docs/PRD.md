# TradingAgents-AShare 产品需求文档 (PRD)

> 版本: v1.0 | 更新日期: 2026-05-10 | 状态: 已上线

---

## 1. 产品概述

### 1.1 产品定位

TradingAgents-AShare 是一款面向**A股和港股投资者**的 AI 智能投研分析工具。通过模拟顶级投研机构的多部门协作流程，利用多智能体（Multi-Agent）技术为用户提供专业级的股票深度分析报告和交易决策建议。

### 1.2 目标用户

| 用户类型 | 特征 | 核心需求 |
|----------|------|----------|
| 个人投资者 | 有一定投资经验，缺乏专业研究团队 | 快速获取专业级分析，辅助决策 |
| 短线交易者 | 关注技术面和资金流向 | 短线机会识别、买卖时机判断 |
| 中线投资者 | 关注基本面和趋势 | 中期趋势判断、持仓建议 |
| 投资学习者 | 希望学习专业分析方法 | 理解分析逻辑，提升投资认知 |

### 1.3 核心价值主张

- **专业级分析**：模拟 14+ 名投研专家协作，覆盖技术面、基本面、消息面、资金面、宏观面
- **多空博弈视角**：通过 Bull/Bear 结构化辩论，避免单一视角偏差
- **风控约束**：激进/稳健/中性三方风控审查，输出带约束条件的交易计划
- **自然语言交互**：无需复杂操作，像对话一样获取分析

## 2. 功能需求

### 2.1 核心功能模块

#### 2.1.1 智能分析 (Analysis)

**功能描述**：用户通过自然语言输入，系统自动识别股票标的、分析周期和关注点，触发多智能体分析流程。

**用户故事**：
- 作为投资者，我希望能输入"分析一下茅台短线机会"，系统自动识别出贵州茅台(600519.SH)并给出短线分析
- 作为投资者，我希望看到每个分析师的实时思考过程，了解分析依据
- 作为投资者，我希望看到多空双方的辩论过程，理解不同视角

**输入格式支持**：
```
"分析一下贵州茅台"
"600519.SH 短线机会"
"调研宁德时代中线趋势"
"腾讯 0700.HK 今天走势"
"比亚迪 002594.SZ 是否适合介入，给出目标价和止损价"
```

**输出内容**：
- 各维度分析师报告 (Market/News/Fundamentals/Macro/SmartMoney)
- 多空研究员辩论记录
- 研究总监综合裁决
- 交易员执行计划 (方向、仓位、入场条件)
- 风控约束条件 (仓位上限、回撤容忍、止损位)
- 最终交易决策 (方向、置信度、目标价、止损价)

**交互流程**：
```
1. 用户输入自然语言查询
2. 系统显示"正在识别意图..."
3. 系统显示"分析已启动，14名Agent正在协作..."
4. 左侧实时展示各Agent状态和分析过程
5. 右侧展示结构化报告 (可切换Tab查看不同维度)
6. 分析完成后展示最终决策卡片
```

#### 2.1.2 双周期分析

**功能描述**：支持同时分析短线(1-5天)和中线(1-3个月)两个周期，输出两份独立报告。

**用户故事**：
- 作为投资者，我希望同时了解一只股票的短线和中线机会，制定不同策略

**实现方式**：
- 系统根据用户输入自动判断周期意图
- 未明确指定时，默认只分析短线
- 明确提到"中线/中期/长期"时，同时分析两个周期
- 两个周期的分析并行执行，独立输出报告

#### 2.1.3 多空辩论可视化

**功能描述**：以时间线形式展示 Bull/Bear 研究员的结构化辩论过程。

**用户故事**：
- 作为投资者，我希望理解为什么看多或看空，看到双方的核心论据

**展示内容**：
- 辩论轮数 (可配置，默认1轮)
- 每轮双方 Claim 和 Rebuttal
- 研究总监的裁决理由

#### 2.1.4 历史报告管理 (Reports)

**功能描述**：结构化存储所有分析结果，支持按标的、日期检索。

**用户故事**：
- 作为投资者，我希望查看之前分析过的股票报告，跟踪建议准确性
- 作为投资者，我希望对比同一股票不同时期的分析变化

**功能点**：
- 报告列表 (按时间倒序)
- 按标的筛选
- 报告详情页 (完整分析内容)
- 决策卡片 (方向、置信度、目标价、止损价)

#### 2.1.5 持仓管理 (Portfolio)

**功能描述**：支持导入持仓数据，系统自动跟踪并纳入分析上下文。

**用户故事**：
- 作为投资者，我希望系统知道我的持仓情况，给出针对性的加减仓建议
- 作为投资者，我希望一键将持仓股票加入定时分析列表

**功能点**：
- 持仓导入 (CSV/Excel)
- 持仓列表展示 (股票、成本、仓位、盈亏)
- 持仓上下文自动带入分析

#### 2.1.6 定时分析 (Scheduled Analysis)

**功能描述**：设置定时任务，自动对自选股进行定期分析。

**用户故事**：
- 作为投资者，我希望每天开盘前自动收到自选股的分析报告
- 作为投资者，我希望系统持续跟踪我的持仓股票

**功能点**：
- 定时任务列表
- 添加/编辑/删除任务
- 执行周期配置 (每日/每周)
- 执行时间配置
- 批量操作
- 连续失败自动停用

#### 2.1.7 跟踪看板 (Tracking Board)

**功能描述**：实时展示持仓股票的行情数据和最新分析摘要。

**用户故事**：
- 作为投资者，我希望在盘中快速查看持仓股票的实时状态

**展示内容**：
- 实时价格、涨跌幅
- 当日最高/最低价
- 持仓盈亏
- 最新分析报告摘要

#### 2.1.8 设置 (Settings)

**功能描述**：配置 LLM 模型、数据源、分析师选择等。

**功能点**：
- LLM 厂商选择 (OpenAI/Anthropic/Google/DeepSeek 等)
- API Key 配置
- 模型选择 (快速/深度)
- 默认分析师选择
- 辩论轮数配置
- 语言选择 (中文/英文)
- 模型 Warmup 测试

### 2.2 非功能性需求

| 需求 | 目标 | 说明 |
|------|------|------|
| 分析响应时间 | < 15 分钟 | 完整分析流程平均耗时 |
| SSE 连接稳定性 | 99.9% | 长连接不中断 |
| 并发用户数 | 50+ | 同时在线分析 |
| 数据准确性 | 依赖数据源 | Tushare/AKShare 等第三方数据 |
| 系统可用性 | 99% | 月度可用时间 |

│       │   ├── 最近报告
│       │   └── 持仓概览
│       ├── Analysis (分析页) [核心]

### 3.2 核心页面：Analysis

**布局**：左右分栏 (4:6 或 5:5)

**左侧 - ChatCopilotPanel**：
- 顶部：输入框 (自然语言)
- 中部：消息列表

  - 系统消息 (左侧，如"分析已启动")
  - Agent 消息 (左侧，带 Agent 头像和名称)

    - 完成状态：报告内容

**右侧 - ReportViewer**：
- Tab 导航：
  - 概览 (最终决策)
  - 分析师报告 (各维度)
  - 辩论过程 (Bull/Bear)
  - 风控约束
- 决策卡片：
  - 方向 (看多/看空/中性)
  - 置信度 (0-100%)
  - 目标价
  - 止损价
- 风险雷达图
- 关键指标

## 4. 技术需求

### 4.1 LLM 需求

| 用途 | 模型要求 | 说明 |
|------|----------|------|
| 意图解析 (Quick) | 轻量级模型 | 提取股票代码、日期、周期 |
| 分析师 (Quick) | 轻量级模型 | 各维度分析，可并行 |
| 研究员 (Quick) | 轻量级模型 | 多空辩论 |
| 交易员 (Quick) | 轻量级模型 | 交易计划 |
| 风控/经理 (Deep) | 强模型 | 综合裁决、最终决策 |

**推荐配置**：
- Quick: `deepseek-v4-flash` (快速、低成本)
- Deep: `deepseek-v4` 或 `gpt-4o` (高质量)

### 4.2 数据源需求

| 数据类型 | A股来源 | 港股来源 | 说明 |
|----------|---------|----------|------|
| 行情数据 | Tushare `daily` | Tushare `hk_daily` | OHLCV |
| 财务数据 | Tushare `daily_basic` | 暂不支持 | PE/PB 等 |
| 新闻数据 | 内置新闻工具 | 内置新闻工具 | 舆情分析 |
| 资金流向 | Tushare `moneyflow` | 暂不支持 | 主力资金 |

### 4.3 存储需求

| 数据 | 存储方式 | 说明 |
|------|----------|------|
| 用户数据 | SQLite/PostgreSQL | 账号、配置、持仓 |
| 分析报告 | SQLite/PostgreSQL | 结构化存储 |
| 任务队列 | 内存/Redis | Job Store |
| 缓存数据 | 内存 | 行情数据缓存 |

## 5. 业务流程

### 5.1 分析主流程

```
开始
  │
  ├──► 用户输入自然语言查询
  │
  ├──► [Intent Parser] LLM 解析意图
  │    ├── 提取 stock_name
  │    ├── 提取 date (默认今天)
  │    ├── 提取 horizons (默认 short)
 │    ├── 提取 focus_areas
  │    └── 提取 user_context (持仓、约束)
  │
  ├──► [Job Store] 创建异步 Job
  │
  ├──► [Data Collector] 获取行情数据
  │    ├── 调用 Tushare/AKShare/yfinance
  │    └── 缓存数据
  │
  ├──► [Analysts] 并行分析 (5-7名)
  │    ├── Market Analyst → 技术面报告
  │    ├── News Analyst → 舆情报告
  │    ├── Fundamentals Analyst → 基本面报告
  │    ├── Macro Analyst → 宏观报告
  │    └── Smart Money Analyst → 资金面报告
  │
  ├──► [Researchers] 多空辩论
  │    ├── Bull Researcher (看多论证)
  │    ├── Bear Researcher (看空反驳)
  │    └── ... (多轮辩论)
  │
  ├──► [Research Manager] 综合裁决
  │    └── 形成投资计划
  │
  ├──► [Trader] 制定交易方案
  │    └── 方向、仓位、入场条件
  │
  ├──► [Risk] 风控辩论
  │    ├── Aggressive Analyst
  │    ├── Conservative Analyst
  │    └── Neutral Analyst
  │
  ├──► [Risk Manager] 最终决策
  │    └── 输出：方向、置信度、目标价、止损价、约束条件
  │
  └──► [Report] 结构化存储报告
       └── 推送 SSE completed 事件
```

### 5.2 用户认证流程

```
注册/登录
  │
  ├──► 邮箱 + 验证码注册
  │
  ├──► JWT Token 签发
  │
  └──► 前端存储 Token
       └── 后续请求携带 Authorization: Bearer <token>
```

## 6. 风险与限制

### 6.1 已知限制

| 限制 | 说明 | 缓解措施 |
|------|------|----------|
| 分析耗时较长 | 完整分析需 5-15 分钟 | 使用更快的模型、减少分析师数量 |
| LLM 幻觉 | AI 可能生成不准确信息 | 多 Agent 交叉验证、风险提示 |
| 数据延迟 | 行情数据非实时 | 明确标注数据时间、使用实时行情补充 |
| 港股财务数据 | Tushare 港股财务接口有限 | 标注数据缺失、使用 yfinance 补充 |
| 并发限制 | 单实例并发能力有限 | 水平扩展、Redis Job Store |

### 6.2 风险提示

- **非投资建议**：系统输出仅供参考，不构成投资建议
- **实盘风险**：证券市场有风险，投资需谨慎
- **数据准确性**：依赖第三方数据源，可能存在延迟或错误
- **模型局限性**：LLM 可能产生幻觉，关键决策需人工复核
