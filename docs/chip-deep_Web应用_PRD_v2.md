# chip-deep Web 应用 — 产品需求文档 (PRD) v2.0

**文档版本**: v2.0（审查优化版）  
**编制日期**: 2026-05-30  
**产品名称**: chip-deep — A股筹码深度分析工具

---

## 从 v1.0 到 v2.0 的核心变更

| 变更项 | v1.0 | v2.0（审查后） | 理由 |
|:--|:--|:--|:--|
| **输出格式** | Markdown + HTML | Markdown + HTML + **JSON数据接口** | 量化用户需要结构化数据而非文本 |
| **数据源** | 仅 Tushare | Tushare + **补充行情** + **财报数据** | 提高数据冗余和可靠性 |
| **缓存策略** | 简单TTL | **分级缓存 + 增量更新** | cyq_chips 数据量大，避免全量重复拉取 |
| **边际变化** | 仅2周对比 | **多窗口对比（1周/2周/4周）** | 不同标的迁移速度差异大 |
| **标的解析** | 精确匹配 | **模糊匹配 + 别名库 + 多解候选** | "茅台""招行"等简称需支持 |
| **错误处理** | 通用错误 | **结构化错误码 + 降级策略** | 部分数据失败时仍输出部分报告 |
| **架构** | 单体 | **模块化 + 插件式分析器** | 便于后续扩展新分析维度 |
| **输出报告** | 文本描述 | **文本 + 数据表格 + 图表 + 评分卡** | 不同用户偏好不同信息密度 |

## 1. 产品概述

### 1.1 产品定位

将 `chip-deep` 技能转化为 Web 应用，用户输入股票代码/名称，一键生成带可视化图表的筹码深度分析报告。覆盖 A 股、科创板、北交所。

### 1.2 核心差异点（vs 同花顺/东方财富）

| 维度 | 同花顺筹码分布 | **chip-deep Web** |
|:--|:--|:--|
| 时间维度 | 当日快照 | **250天演变追踪** |
| 价格区间分析 | 全分布 | **用户自定义区间分析** |
| 底部判断 | 无 | **六维综合评分矩阵** |
| 多标的对比 | 无 | **横向对比（Phase 2）** |
| 报告导出 | 截图 | **Markdown/HTML/JSON** |
| 边际变化 | 无 | **1/2/4周多窗口对比** |

## 2. 完整数据源与 API 清单

### 2.1 核心数据源：Tushare Pro

| 接口名 | 用途 | 必填参数 | 积分要求 | 数据量/次 | 更新频率 |
|:--|:--|:--|:--:|:--:|:--:|
| `stock_basic` | 标的解析（名称→ts_code） | `name` 或 `ts_code` | 200 | 1行 | 每日 |
| `trade_cal` | 交易日历 | `start_date` + `end_date` | 200 | ~250行 | 静态 |
| `daily` | 日线行情 | `ts_code` + 日期范围 | 200 | ~250行 | 盘后 |
| `pro_bar` | 复权行情（备用） | `ts_code` + 日期范围 | 200 | ~250行 | 盘后 |
| **`cyq_perf`** | 筹码性能指标 | `ts_code` + 日期范围 | 5000 | ~250行 | 每日18-19点 |
| **`cyq_chips`** | 筹码分布明细 | `ts_code` + `trade_date` | 5000 | ~100行/日 | 每日18-19点 |
| `dividend` | 股息记录（补充） | `ts_code` | 2000 | ~10行 | 年报期 |

### 2.2 补充数据源（备用/增强）

| 接口名 | 用途 | 触发条件 |
|:--|:--|:--|
| `forecast` | 业绩预告 | 当分析报告中需基本面佐证时 |
| `fina_indicator` | 财务指标（ROE等） | 当获利盘<15%需区分低胜率类型时 |
| `moneyflow` | 资金流 | 当分析价格异动原因时（Phase 2） |
| `limit_list_d` | 涨停/跌停记录 | 当近期有涨跌停时补充说明 |

### 2.3 数据依赖矩阵

```
分析维度                   所需数据
─────────               ─────────
标的解析    →  stock_basic
交易日历    →  trade_cal
价格走势    →  daily
成本结构    →  cyq_perf
筹码分布    →  cyq_chips
边际变化    →  cyq_chips（2个时点）
股息率      →  dividend（可选）
六维评分    →  cyq_perf + cyq_chips + daily
```

### 2.4 数据拉取性能预算

| 步骤 | 接口 | 预估耗时 | 并行/串行 |
|:--|:--|:--:|:--:|

| 日线行情 | daily | 1.5s | 并行 |
| 成本指标 | cyq_perf | 2.0s | 并行 |

## 4. 架构审查优化要点

### 4.1 v1.0 问题 → v2.0 改进

| 问题 | 风险 | 改进方案 |
|:--|:--|:--|
| cyq_chips ×6 串行拉取耗时 3s+ | 可能触及Tushare限流 | **批量拉取**（一次请求多日期）+ **缓存命中跳过** |
| 所有数据强依赖Tushare | 单点故障 | **降级策略**：cyq_chips失败时用daily模拟筹码分布 |
| 六维评分标准固定 | 不适用于所有标的类型 | **动态权重**：银行股和科技股权重不同 |
| 边际变化仅对比2周前 | 暴涨暴跌标的2周变化过大 | **多窗口**：1周/2周/4周，取最稳定的窗口 |
| 无标的别名库 | "茅台""招行"无法识别 | **内置别名映射表** + 模糊搜索 |
| 无健康检查 | 服务挂了不知道 | **/health** + **Tushare Token 启动时校验** |
| 报告仅文本+图表 | 量化用户无法直接使用 | **JSON 数据接口** + 结构化数据输出 |

### 4.2 降级策略矩阵

| 故障场景 | 降级行为 | 用户提示 |
|:--|:--|:--|
| cyq_chips 全部失败 | 用 daily 成交量模拟筹码分布 | "实时筹码数据暂不可用，已使用成交量近似估算" |
| cyq_perf 失败 | 仅输出价格走势和基本统计 | "成本结构数据暂不可用" |
| daily 行情失败 | 使用 pro_bar 复权行情替代 | "行情数据使用复权价" |
| cyq_chips 部分日期失败 | 可用日期生成报告，标注缺失日期 | "部分日期筹码数据缺失（标注）" |
| Tushare 整体不可用 | 返回缓存报告（如有）或错误提示 | "数据源暂时不可用，请稍后重试" |

### 4.3 插件式分析器架构

```

├── stages/              # 各分析阶段（可独立替换）
│   ├── price_stage.py       # 价格走势分析
│   ├── chip_stage.py        # 筹码分布分析
│   ├── cost_stage.py        # 成本结构分析
│   └── dim6_stage.py        # 六维判断
│
├── calculators/         # 计算工具（可复用）
```

## 6. 风险矩阵（v2 更新）

| 风险 | 影响 | 概率 | 检测方式 | 应对 |
|:--|:--|:--:|:--|:--|
| Tushare Token 过期 | 服务完全不可用 | 低 | `/health` 启动校验 + 每日定时检查 | 提前7天邮件告警 |
| Tushare 积分超限 | 高权限接口失败 | 中 | 每次请求后检查剩余积分 | 降级到低精度分析 |
| cyq_chips 数据延迟 | 报告非最新 | 中 | 对比数据日期与当前日期 | 页面明确标注数据日期 |
| Redis 宕机 | 缓存失效，响应变慢 | 低 | `/health` 检查 | 自动降级为无缓存模式 |
| 高并发（游资行情日） | 响应超时 | 中 | 监控 P95 响应时间 | 自动扩容 + 队列限流 |
| Tushare API 变更 | 接口报错 | 低 | 版本号监控 | 适配器模式隔离变更 |

| 维度 | v1.0 | v2.0（审查后） | 工作量变化 |
|:--|:--|:--|:--:|
